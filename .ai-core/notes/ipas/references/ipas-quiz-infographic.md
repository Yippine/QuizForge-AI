## 三、陷阱選項設計原則（五大手法）

① **技術相近混淆** → 名稱相似但用途不同
　　VAE 用於「異常偵測（學習正常分布）」≠ VAE 用於「圖像生成」

② **因果倒置** → 現象描述正確，但指向錯誤原因
　　上線後準確率下降 → 答案是 Data Drift，不是「過擬合」

③ **範疇錯誤** → 把不屬於某概念的功能硬塞進去
　　PoC 的定義不包含「建立長期治理框架」

④ **程度誇大** → 用「任何／完全／所有」包裝部分成立的技術
　　Homomorphic Encryption 只能做「特定運算」，非「任何運算」

⑤ **多陳述挖坑** → 在 5～6 條陳述中，某條刻意使用絕對詞製造假錯誤
　　「遷移學習必須使用完全相同的資料格式」→ 錯誤，必須≠事實

## 四、115 年新增高機率考點

### 📘 科目一（L11）— 7 大新考點

- **Flash Attention**（3題 T2）：IO 感知算法，減少 GPU HBM 讀寫，非減少運算量
- **VAE vs GAN vs Diffusion**（5題 T2/T3）：用途差異——VAE→異常偵測／GAN→高品質圖像生成／Diffusion→可控生成
- **RLHF 流程**（4題 T2）：偏好資料蒐集 → 訓練獎勵模型 → PPO 強化學習優化 LLM
- **post-hoc vs intrinsic XAI**（5題 T2）：LIME/SHAP = 模型訓練後解釋（後處理），≠ 模型本身透明（決策樹）
- **Batch vs Real-time Inference**（3題 T1）：批次（高吞吐/延遲高）vs 即時（低延遲/成本高）
- **金融機構AI作業規範**（4題 T1）：必要揭露事項、模型風險管理義務
- **去識別化策略**（3題 T1）：政府資料開放情境下的匿名化手法分類

### 📗 科目二（L12）— 9 大新考點

- **Vibe Coding**（5題 T1/T2）：AI 輔助開發模式，AI生成代碼「必須人工審查」才可上線
- **AgentKit**（4題 T2）：OpenAI 2025年，支援 Agents 建構／工具整合／多步任務流程
- **SynthID**（3題 T1）：Google Veo，每幀嵌入不可見數位浮水印，用於AI內容溯源
- **RFT（Reinforcement Fine-tuning）**（4題 T2）：用 reward 訊號調整模型行為偏好，≠ 監督微調
- **Homomorphic Encryption**（3題 T3）：在加密狀態下執行「特定」運算，保護資料隱私
- **Token Economics ROI 計算**（5題 T2）：月省成本 = 人工費 − Token費；回收期 = 整合費 ÷ 月省
- **MCP vs RAG**（4題 T2）：MCP = 工具呼叫與系統互動；RAG = 外部知識補充，兩者定位不同
- **Encoder-Decoder vs Decoder-only**（3題 T2）：前者適合翻譯/摘要，後者適合生成/對話
- **PoC 範疇界定**（3題 T1）：PoC 只驗證技術可行性，不包含長期治理框架建立
